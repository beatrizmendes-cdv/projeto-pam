Responsabilidades combinadas:

- client-*.tsx: tela interativa com use client; hooks de consulta, busca, listagem, total, estados de carregamento/erro e, futuramente, abertura de modal e seleção do registro.

- format-payload.ts: função pura que transforma os valores validados no DTO de entrada da API. Sem requisição. Extensão .ts é suficiente.
- hooks: useQuery para leitura e futuramente useMutation para escrita e invalidação do cache.
- lib/api.ts: instâncias configuradas do cliente HTTP.
- clients/projeto-pam: código GERADO. Não editar manualmente para implementar telas ou regras.
- components: componentes visuais já existentes, reaproveitados.

Divisão simples para salvar: o formulário valida e chama uma prop onSubmit com valores válidos; a tela cliente formata o payload e chama uma mutation; após sucesso, atualiza a listagem/invalida a query. DOCKER E AMBIENTE QUE A USUÁRIA CONFIRMOU FUNCIONAR

Objetivo: Docker completo (front 3000, back 4000 e PostgreSQL) + front de desenvolvimento no terminal em 3001 consumindo a mesma API Docker.
- PostgreSQL: serviço postgres, porta interna 5432, publicada como 5433 no host, volume postgres_data.
- Backend Docker: DB_HOST=postgres e DB_PORT=5432 no environment do serviço server, além das credenciais adequadas.
- Serviço postgres: usa POSTGRES_USER, POSTGRES_PASSWORD e POSTGRES_DB. Não colocar nele as variáveis DB_* destinadas ao Nest.
- app.module.ts lê DB_HOST, DB_PORT, DB_USERNAME, DB_PASSWORD e DB_DATABASE. DATABASE_URL isolada não era usada.
- Backend local tinha defaults localhost:5433; isso explica por que funcionava com banco Docker mesmo sem DB_*.
- Erro EADDRINUSE na porta 4000 ocorreu ao iniciar backend no terminal quando o Docker já usava essa porta.
- main.ts deve permitir CORS para http://localhost:3000 e http://localhost:3001 nesse ambiente.
- URL do cliente no navegador: http://localhost:4000, quando navegador e Docker estão na mesma máquina. localhost em outra máquina aponta para a outra máquina.
- Não alterar CORS para * indiscriminadamente, não apagar volume de dados, não executar down -v.
- Swagger local: http://localhost:4000/api. Failed to fetch é genérico, não prova CORS. Examinar URL e logs antes de concluir.
- AppModule usa synchronize: true; gerar Swagger inicializa o app e conecta ao banco, não é só leitura estática de TypeScript.
